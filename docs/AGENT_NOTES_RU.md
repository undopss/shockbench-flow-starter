# Памятка по Python и агенту ShockBench-Flow

Эта памятка предназначена для тех, кто только начинает программировать. Она
объясняет основные слова из [агента `mine`](../agents/mine/agent.py), структуру
данных среды и то, как решение превращается в отправки.

> Размеры ниже, помеченные **Small**, относятся к сети Small. В Tiny и Full
> количество узлов, рёбер, действий и размеры массивов другие. В коде нужно
> читать размеры и индексы из `config`, а не рассчитывать на число 108 или
> любой другой размер из примера.

## 1. Самая короткая схема

Каждую неделю среда примерно делает следующее:

1. Передаёт агенту `observation` — наблюдение о сети на этой неделе.
2. Вызывает метод `Agent.act(observation)`.
3. Получает от агента словарь с решением, например `{"flows": ...}`.
4. Применяет перевозки, производство, спрос и затраты.
5. Переходит к следующей неделе и снова вызывает `act`.

При начале эпизода среда один раз вызывает `Agent(config)`. Конфигурация
описывает постоянную структуру сети, а наблюдение обновляется каждую неделю.

## 2. Основные слова Python

| Слово | Простое объяснение | Пример |
| --- | --- | --- |
| Переменная | Имя, под которым хранится значение | `week = 3` |
| Тип значения | Что именно хранится: число, текст, список и т. п. | `3` — целое число, `"lng"` — текст |
| Список (`list`) | Упорядоченный набор; счёт позиций начинается с нуля | `["а", "б"]`; элемент `0` — `"а"` |
| Словарь (`dict`) | Набор пар «ключ → значение» | `{"week": 3}`; `["week"]` достаёт `3` |
| Индекс | Номер позиции в списке или массиве; начинается с нуля | `items[0]` — первый элемент |
| Функция | Именованный кусок кода, который можно вызвать | `int("3")` превращает текст в число |
| Метод | Функция, принадлежащая объекту или классу | `agent.act(obs)` |
| Класс | Чертёж, по которому создают объект | `class Agent:` |
| Объект / экземпляр | Конкретно созданная сущность класса | созданный средой `Agent(config)` |
| Аргумент | Значение, переданное функции или методу | `observation` в `act(observation)` |
| Возврат (`return`) | Результат, который функция отдаёт вызвавшему коду | `return {"flows": flows}` |
| Цикл `for` | Повторяет код для каждого элемента | `for edge in edges:` |
| Условие `if` | Выполняет код, если проверка истинна | `if mask[i] == 1:` |
| `None` | Специальное значение «ничего / не задано» | `lane is None` |
| `True` / `False` | Логические значения «да» / «нет» | `stock_known = True` |

### Квадратные скобки: список и словарь

Одинаковые скобки используются для разных целей:

```python
observation["week"]   # получить значение по ключу "week" из словаря
observation["week"][0]  # взять первый элемент массива недели
```

В первой строке `"week"` — **ключ словаря**. Во второй `[0]` — **индекс
массива**. Ключи обычно текстовые, индексы — числа.

### `self`

В методе класса `self` означает «этот конкретный экземпляр агента». Данные,
записанные как `self.edges` в начале эпизода, остаются доступны на следующих
неделях как `self.edges`. Поэтому `self` позволяет хранить подготовленные
таблицы между вызовами `act`.

### `enumerate` и `zip`

`enumerate(список)` перебирает список, одновременно давая индекс и значение:

```python
for index, name in enumerate(["узел_A", "узел_B"]):
    print(index, name)
# 0 узел_A
# 1 узел_B
```

`zip(a, b)` объединяет значения с одинаковыми позициями:

```python
list(zip(["ребро_0", "ребро_1"], [6, 7]))
# [("ребро_0", 6), ("ребро_1", 7)]
```

Если длины списков различаются, `zip` остановится на самом коротком. В
`mine` списки полей action slots задуманы так, чтобы их позиции соответствовали
друг другу.

### Генераторы списков и словарей

Короткая запись:

```python
[edges["u0"][edge] for edge in slots["edge"]]
```

означает примерно то же, что:

```python
capacities = []
for edge in slots["edge"]:
    capacities.append(edges["u0"][edge])
```

`append` добавляет элемент в конец списка. Вариант в фигурных скобках:

```python
{name: index for index, name in enumerate(names)}
```

создаёт словарь. Такая конструкция называется **генератором словаря**.

## 3. Что такое NumPy

NumPy — библиотека Python для удобной работы с числовыми массивами. В файле
пишут:

```python
import numpy as np
```

Слово `import` подключает библиотеку, а `as np` задаёт короткое имя: далее
вместо `numpy.array(...)` можно написать `np.array(...)`.

Важные команды NumPy, встречающиеся в `mine`:

| Запись | Что делает |
| --- | --- |
| `np.array(values, dtype=float)` | Создаёт числовой массив с числами с плавающей точкой |
| `np.zeros(n)` | Создаёт массив длины `n`, заполненный нулями |
| `np.zeros_like(array)` | Создаёт нулевой массив той же формы, что `array` |
| `np.cumsum(array, axis=1)` | Считает накопительную сумму по столбцам |
| `np.all(mask)` | Возвращает `True`, только если все значения истинны |

Пример накопительной суммы:

```python
np.cumsum([10, 12, 8])
# [10, 22, 30]
```

Если массив двумерный, `axis=1` означает: обрабатывать каждую строку слева
направо. В `mine` это суммирует спрос по неделям отдельно для каждого
потребителя.

NumPy также позволяет выполнять операцию сразу над всеми элементами:

```python
capacity = np.array([10, 20, 30])
mask = np.array([1, 0, 1])
capacity * mask
# [10, 0, 30]
```

Это поэлементное умножение: первый элемент умножается на первый, второй —
на второй и т. д.

## 4. Разрешённые библиотеки агента

По правилам репозитория агент на сервере может использовать стандартную
библиотеку Python, NumPy, SciPy и PyTorch (CPU).

- **Стандартная библиотека Python** — то, что идёт вместе с Python: циклы,
  словари, списки, `int`, `min`, `max`, `zip`, `enumerate` и другие встроенные
  средства. Для неё не нужно устанавливать отдельный пакет.
- **NumPy** — массивы и численные операции. Используется в текущем `mine`.
- **SciPy** — научные алгоритмы, в том числе численная оптимизация. Может
  пригодиться для MPC или других математических планировщиков.
- **PyTorch** — библиотека для нейронных сетей. Нужна, если агент запускает
  обученную модель; текущий `mine` её не использует.

То, что пакет установлен для обучения или доступен в ноутбуке, не обязательно
означает, что его можно импортировать в отправляемом агенте. Проверяйте агент
командой `uv run sbf check mine --task=small`.

## 5. Слова о сети поставок

Представьте карту с точками, дорогами и грузами:

- **Узел (`node`)** — точка сети: источник, терминал, завод, склад или рынок.
- **Ребро (`edge`)** — отдельное соединение между двумя узлами. По нему товар
  перемещается из `tail` (начала) в `head` (конец).
- **Маршрут / lane (`lane`)** — путь, иногда состоящий из нескольких рёбер.
  Например, морской путь через проливы.
- **Товар / commodity** — тип перевозимого товара, например LNG, crude или wafer.
- **Пропускная способность / capacity** — сколько товара участок или действие
  могут перевезти за неделю.
- **Пролив / chokepoint** — узкое место маршрута, состояние которого может
  ограничить перевозку.
- **Поставка в пути / pipeline** — груз, уже отправленный ранее, но ещё не
  прибывший.
- **Спрос / demand** — сколько товара хочет получить конкретный рынок.
- **Накопленный дефицит / backlog** — спрос прошлых недель, который ещё не был
  удовлетворён.
- **Фрахт / freight** — плата за перевозку.
- **Тариф / tariff** — дополнительная плата, связанная с маршрутом или
  торговыми ограничениями.

В таблицах сети узлы, рёбра, товары и маршруты обычно обозначаются целыми
числами-индексами. Чтобы выяснить, что означает индекс `edge = 3`, нужно
посмотреть на элемент 3 в таблице рёбер. Не следует считать, что индекс 3
всегда означает одно и то же во всех сетях.

## 6. Что означают `config`, `static`, `layout` и `spaces`

### `config`

`config` — словарь исходной информации об эпизоде. Среда передаёт его в
конструктор один раз:

```python
agent = Agent(config)
```

В нём есть, среди прочего:

| Поле | Значение |
| --- | --- |
| `config["static"]` | Постоянные таблицы сети: узлы, рёбра, товары, маршруты, action slots |
| `config["layout"]` | Значение индексов в массивах наблюдений |
| `config["spaces"]` | Формы и типы входных и выходных массивов |
| `config["T"]` | Длина эпизода в неделях |
| `config["regime"]` | Режим наблюдений, например `standard` |
| `config["policy_seed"]` | Seed для генератора случайных чисел, если агент использует случайность |

Текущий `mine` читает `static` и `layout`; остальные поля ему сейчас не нужны.

### `static`

`static` — справочные таблицы сети. В текущем агенте используются:

- `static["edges"]` — таблица рёбер; в частности, `tail`, `head`, `u0`;
- `static["lanes"]` — таблица маршрутов; `edges` у маршрута содержит индексы
  его рёбер, `chokepoints` — индексы проливов/узких мест;
- `static["action_slots"]` — связь каждого возможного действия с ребром,
  товаром и маршрутом;
- `static["sinks"]` — узлы конечного спроса и соответствующие товары.

`u0` — номинальная, исходная мощность ребра. Текущая мощность на конкретной
неделе находится в `observation["graph_now.u"]` и может отличаться.

### `layout`

`layout` объясняет, что обозначает каждая позиция в плотном массиве. Например,
если `layout["stock_slots"][12] == [34, 6]`, то позиция 12 в `stock.qty`
относится к запасу товара 6 в узле 34.

Часто используемые таблицы:

- `layout["stock_slots"]` — соответствие строк запасов парам `(узел, товар)`;
- `layout["demands"]` — соответствие строк спроса парам `(рынок, товар)`;
- `layout["chokepoints"]` — соответствие позиций массива `graph_now.open`
  конкретным узким местам.

### `spaces`

`spaces` сообщает допустимую форму (размер) и тип данных массивов действия и
наблюдения. Код обычно должен получать размеры из него или из наблюдения, а не
записывать вручную. Например, длина `flows` равна числу action slots для данной
сети.

## 7. Action slot и действие `flows`

**Action slot** — одна позиция в массиве `flows`, то есть один вариант
отправить один товар по заданному ребру/маршруту.

На Small в документации 108 action slots, поэтому там `flows` содержит 108
чисел. В Tiny и Full размер другой.

Для каждого slot таблица `static["action_slots"]` хранит:

- `edge` — индекс ребра, на котором начинается действие;
- `k` — индекс товара;
- `lane` — индекс полного маршрута либо `None`, если это одно ребро без lane.

Если `lane` указан, путь может содержать несколько рёбер. Поэтому slot — не
обязательно «только одно ребро»: это команда диспетчеру отправить количество
груза по конкретному варианту маршрута.

`flows[i]` — запрошенное количество для action slot `i`. Ноль означает
«ничего не отправлять по этому действию». Среда применяет ограничения сети:
запас, мощность, запреты и другие правила.

## 8. `action_mask` и другие маски

Маска — массив флагов, который сопоставлен позициям другого массива.
В `action_mask`:

- `1` — действие разрешено с точки зрения запрета маршрута;
- `0` — действие запрещено сейчас, например санкцией.

Маска не гарантирует, что маршрут открыт или имеет ненулевую мощность.
Открытость узких мест читается из `graph_now.open`, а текущая мощность — из
`graph_now.u`.

В `mine` начальное решение задаётся так:

```python
flows = self.capacity * observation["action_mask"]
```

Если мощность равна `[10, 20, 30]`, а маска `[1, 0, 1]`, исходные `flows`
будут `[10, 0, 30]`.

Маска вида `имя.поля.observed` отвечает на другой вопрос: **видно ли значение
этой позиции?** Единица означает, что значение наблюдалось; ноль может означать
скрытое значение или padding (заполнитель). Поэтому «данных не видно» нельзя
автоматически трактовать как «значение точно равно нулю».

## 9. Главные поля `observation`

`observation` — обновляемый словарь состояния на текущей неделе. Примеры
размеров ниже относятся к документации Small.

| Ключ | Пример формы Small | Что содержит |
| --- | ---: | --- |
| `week` | `(1,)` | Номер текущей недели, нумерация начинается с 1 |
| `stock.qty` | `(59,)` | Запас по строкам из `layout["stock_slots"]` |
| `backlog.qty` | `(8,)` | Невыполненный спрос по строкам `layout["demands"]` |
| `demand_forecast.qty` | `(8, 8)` | Прогноз спроса: строки — направления спроса, столбцы — недели |
| `pipeline.edge` | `(269,)` | Индексы рёбер записей о грузах в пути |
| `pipeline.k` | `(269,)` | Индексы товаров в тех же записях |
| `pipeline.arrival_week` | `(269,)` | Неделя прибытия соответствующей записи |
| `pipeline.qty` | `(269,)` | Количество в соответствующей записи |
| `graph_now.u` | `(115,)` | Текущая мощность каждого ребра |
| `graph_now.c` | `(115,)` | Текущая стоимость фрахта по каждому ребру |
| `graph_now.tau` | `(115,)` | Время прохождения каждого ребра в неделях |
| `graph_now.tariff` | `(115, 8)` | Тариф по паре (ребро, товар) |
| `graph_now.open` | `(7,)` | Доля открытости каждого узкого места: обычно от 0 до 1 |
| `action_mask` | `(108,)` | Доступность каждого action slot с точки зрения запретов |

Для обычного массива `x` среда, как правило, также даёт `x.observed`.
Исключения перечислены в заголовке [справочника полей Small](./fields/small.md).

Поля одной записи `pipeline` нужно читать вместе по одинаковому индексу `i`:

```python
edge = observation["pipeline.edge"][i]
commodity = observation["pipeline.k"][i]
arrival = observation["pipeline.arrival_week"][i]
quantity = observation["pipeline.qty"][i]
```

Это одна запись о грузе: ребро, товар, неделя прибытия и количество. В Python
имена полей с точками — обычные текстовые ключи словаря, а не выражения вроде
`observation.pipeline.edge`.

## 10. Переменные текущего `mine`

### Подготовка в `__init__`

| Переменная | Для чего нужна |
| --- | --- |
| `static`, `layout` | Локальные короткие имена для справочных таблиц и карты индексов |
| `edges`, `lanes` | Таблицы участков сети и многорёберных маршрутов |
| `self.edges` | Таблица рёбер, сохранённая между недельными вызовами |
| `slots` | Таблица action slots: номер ребра, товара и lane для каждого действия |
| `self.capacity` | Номинальная мощность каждого action slot из `edges["u0"]` |
| `self.demands` | Список пар `(узел, товар)` в порядке строк спроса |
| `self.demand_index` | Словарь: пара `(узел, товар)` → индекс строки спроса |
| `self.stock_index` | Словарь: пара `(узел, товар)` → индекс строки запаса |
| `self.slot_routes` | Для каждого slot хранит индекс спроса (или `None`) и путь из индексов рёбер |
| `self.demand_slots` | Для каждой строки спроса хранит список прямых action slots до этого рынка |
| `chokepoint_index` | Словарь: индекс узкого места в сети → позиция в `graph_now.open` |
| `self.route_chokepoints` | Для каждого slot список позиций узких мест, через которые проходит lane |
| `self.pipeline_destinations` | Пара `(узел-получатель, товар)` → строка соответствующего спроса |

`self.` обозначает данные, сохранённые внутри агента. Например, `self.capacity`
создаётся один раз, а потом используется при каждом вызове `act`.

### Решение в `act`

| Переменная | Для чего нужна |
| --- | --- |
| `flows` | Итоговый план количеств для action slots; сначала максимум на разрешённых slots, затем корректировки |
| `week` | Номер текущей недели |
| `forecast` | Прогноз количества спроса на горизонте нескольких недель |
| `forecast_seen` | Маска, показывающая, какие значения прогноза видны |
| `stock`, `stock_seen` | Значения текущего запаса и маска их наблюдаемости |
| `backlog`, `backlog_seen` | Невыполненный спрос и маска наблюдаемости |
| `need` | Накопительный спрос по неделям прогнозного горизонта |
| `arrivals` | Накопительные объёмы видимых грузов в пути, которые прибудут прямо к рынкам |
| `pipeline_seen` | Маска действительных записей грузов в пути |
| `edges` | Локальная ссылка на сохранённую таблицу рёбер |
| `current_stock` | Запас по строкам спроса, удобный для расчёта дефицита |
| `stock_known` | Флаг `True`/`False`: известно ли значение запаса для строки спроса |
| `demand`, `slots` | Индекс конкретного спроса и прямые action slots для него |
| `cumulative_need` | Накопительная потребность с учётом backlog |
| `available` | Текущий запас плюс уже ожидаемые прибытия |
| `candidates` | Кандидатные прямые маршруты вместе с ценой, сроком и доступной мощностью |
| `slot`, `route` | Текущий action slot и последовательность рёбер его пути |
| `lead`, `delay` | Срок пути и расчётное смещение прибытия относительно горизонта |
| `route_cost` | Сумма текущего фрахта рёбер пути |
| `route_capacity` | Оценка допустимого объёма на маршруте после ограничений |
| `delays` | Словарь: action slot → срок доставки со сдвигом |
| `horizon` | Индекс недели внутри горизонта прогноза; начинается с 0 |
| `planned` | Уже запланированный этим агентом объём для этого спроса к данному горизонту |
| `deficit` | Оценка оставшейся потребности после запаса, прибытий и плана |
| `quantity` | Объём, который добавляется к выбранному маршруту |
| `remaining_capacity` | Ещё не использованная мощность текущего кандидата |

## 11. Как проходит одно решение в `mine`

### Шаг 1: начать с максимума

```python
flows = self.capacity * observation["action_mask"]
```

Каждый разрешённый маршрут изначально получает номинальный максимум, а
запрещённый — ноль. Позже агент изменит прямые поставки к рынкам, если сможет
надёжно оценить спрос и доступный товар.

### Шаг 2: посчитать накопительный спрос

```python
need = np.cumsum(forecast * forecast_seen, axis=1)
```

Если прогноз на три недели `[10, 12, 8]`, то накопительный спрос будет
`[10, 22, 30]`. Умножение на `forecast_seen` обнуляет невидимые элементы.

### Шаг 3: учесть груз, который уже едет

Цикл `for ... in zip(...)` читает несколько массивов pipeline параллельно.
`continue` означает «пропустить эту запись и перейти к следующей». Для
наблюдаемой записи агент:

1. Находит узел назначения по таблице рёбер.
2. Проверяет, относится ли товар к одному из конечных спросов.
3. Считает `offset = arrival_week - week`.
4. Если груз прибудет в пределах прогноза, добавляет его количество в
   соответствующую неделю.

`arrivals = np.cumsum(arrivals, axis=1)` затем превращает прибытия в
накопительный объём: к третьей неделе учитываются грузы, прибывающие на первой,
второй и третьей.

### Шаг 4: узнать запас и проверить качество данных

Для каждого спроса код находит соответствующую строку запаса. Если строка
отсутствует или `stock_seen` сообщает, что значение скрыто, он отмечает запас
неизвестным.

Проверка в начале цикла по спросу требует, чтобы были известны нужный запас,
backlog и весь прогноз. Если данных не хватает, эта группа прямых поставок не
пересчитывается: сохраняются исходные `flows` для неё.

### Шаг 5: оценить прямые маршруты

Для каждой прямой поставки к потребителю код вычисляет:

1. **Срок:** складывает `graph_now.tau` по рёбрам пути.
2. **Стоимость фрахта:** складывает `graph_now.c` по рёбрам пути.
3. **Мощность:** берёт наименьшее из номинала action slot и мощностей рёбер.
4. **Открытость:** уменьшает мощность при закрытии узких мест, если наблюдение
   об их открытости есть.

Кандидаты сортируются по стоимости, а затем по сроку. Это эвристика: она
сначала пытается использовать более дешёвый маршрут, а не решает глобальную
задачу оптимизации всей сети.

### Шаг 6: отправить оценённый дефицит

Для каждого маршрута и недели прогноза код считает примерно следующее:

```text
дефицит = накопленный спрос - (текущий запас + ожидаемые прибытия) - уже запланированное
```

Если дефицит положительный, агент добавляет поставку, ограниченную двумя
значениями: остатком дефицита и оставшейся мощностью маршрута.

### Шаг 7: вернуть действие

```python
return {"flows": flows}
```

Возвращается словарь с массивом потоков. Позиция `flows[i]` относится к
action slot `i`. Агент не передаёт `override_qty` и `release_mode`; для этих
дополнительных частей действия используется поведение среды по умолчанию.

## 13. Что этот агент пока не делает

Текущий `mine`:

- корректирует только маршруты, которые сразу доходят до конечного потребителя;
- оставляет остальные действия на первоначальном плане максимальной отправки;
- учитывает фрахт `graph_now.c` при сортировке прямых маршрутов, но отдельно не
  добавляет тариф `graph_now.tariff` в эту оценку;
- использует прогноз спроса, но не знает истинный случайный спрос и будущие
  нарушения;
- не строит полную оптимизационную модель и не является MPC;
- при недостатке нужных наблюдений оставляет первоначальные потоки для
  соответствующего спроса.

Эти ограничения полезно помнить при объяснении результатов и при выборе
следующего улучшения.

## 14. Полезные команды проекта

Команды запускаются через `uv run`, чтобы использовать окружение из lock-файла:

```bash
# Проверить формат агента и время работы на Small
uv run sbf check mine --task=small

# Оценить только mine на стандартном dev-наборе Small
uv run sbf evaluate mine --task=small

# Сравнить mine с отправкой максимума на одних и тех же эпизодах
uv run sbf compare mine template --task=small --cpu_budget
```

`evaluate` отвечает «каков RSS этого агента на выбранном наборе?». `compare`
отвечает «какова разница между двумя агентами на тех же сценариях?».
Для проверки, помогло ли изменение, обычно полезнее `compare`.
